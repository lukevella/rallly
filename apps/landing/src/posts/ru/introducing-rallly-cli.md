Раньше для самостоятельного размещения Rallly нужно было скопировать пример `docker-compose.yml`, вручную отредактировать его, выбрать собственный обратный прокси и подключить S3-бакет, если требовалась загрузка изображений. Это работало, но каждая установка немного отличалась, и вопрос «а точно ли я правильно настроил этот параметр?» регулярно возникал в письмах в службу поддержки.

Поэтому мы создали полноценный CLI, который берёт на себя установку, настройку и повседневное управление.

## Установка одной командой

```sh
curl -fsSL https://get.rallly.co | bash
```

Установщик проверяет ваше окружение, помогает настроить всё необходимое (домен, контактный адрес службы поддержки, SMTP), создаёт секреты и запускает все компоненты. Ничего не нужно редактировать вручную.

Теперь работающий экземпляр включает:

- сам **Rallly**
- **PostgreSQL** для базы данных
- **Traefik** в качестве обратного прокси с автоматическими сертификатами Let's Encrypt
- **Garage** для совместимого с S3 объектного хранилища, поэтому загрузка аватаров и изображений работает сразу

Теперь вам не нужно самостоятельно подключать прокси или объектное хранилище, чтобы получить полностью готовый экземпляр. Если вы предпочитаете использовать внешние сервисы (управляемый Postgres, AWS S3, собственный Nginx или Caddy), это тоже возможно: укажите соответствующие переменные в `.env`, и встроенные контейнеры этих сервисов просто не будут запущены.

## Управление через CLI

После установки всё выполняется с помощью CLI `rallly.sh`:

```sh
./rallly.sh start          # Start all services
./rallly.sh stop           # Stop all services
./rallly.sh restart        # Apply .env changes
./rallly.sh status         # Show service status
./rallly.sh logs           # Stream logs
./rallly.sh update         # Pull latest images and recreate containers
./rallly.sh backup         # Back up the database to ./backups/
```

Обновление теперь выполняется одной командой. `./rallly.sh update` загружает последние образы, пересоздаёт контейнеры и сохраняет ваши данные и настройки. По умолчанию CLI использует тег `lukevella/rallly:4`, поэтому вы автоматически будете получать совместимые выпуски 4.x.

Кроме того, благодаря большему контролю над стеком в будущем мы сможем добавлять новые сервисы, не усложняя процесс установки и не заставляя пользователей редактировать файлы compose.

## Вы уже самостоятельно размещаете Rallly?

Если Rallly уже работает у вас на основе вручную отредактированного `docker-compose.yml` или `config.env`, ознакомьтесь с пошаговым [руководством по миграции](https://support.rallly.co/self-hosting/migration), которое поможет обновиться до версии 4.10 и перейти на CLI без потери данных. Самое важное, что нужно перенести, — это `SECRET_PASSWORD`, который используется для шифрования сеансов.
