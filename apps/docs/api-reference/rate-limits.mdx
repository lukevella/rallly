All endpoints share two limits per space:

| Window | Limit |
| --- | --- |
| Per minute | 60 requests |
| Per day | 5,000 requests |

Both are fixed windows that open with the first request and reset when they expire. Limits apply to the space, not the key, so creating more keys does not increase throughput.

## Headers

Every response to an authenticated request carries the standard `RateLimit-*` headers:

| Header | Meaning |
| --- | --- |
| `RateLimit-Policy` | Both limits and their window lengths |
| `RateLimit-Limit` | The limit closest to being exhausted |
| `RateLimit-Remaining` | Requests left in that window |
| `RateLimit-Reset` | Seconds until that window resets |

Responses sent before the limiter runs, such as `401`, `403` and the maintenance `503`, do not include them.

## Exceeding a limit

When either limit is exhausted the API responds with `429 Too Many Requests`, a `RATE_LIMIT_EXCEEDED` error body and a `Retry-After` header with the number of seconds to wait.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 23
RateLimit-Limit: 60
RateLimit-Remaining: 0
RateLimit-Reset: 23
```

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Rate limit exceeded. Retry after the time indicated in the Retry-After header."
  }
}
```

Wait for `Retry-After` before retrying. Do not retry on a fixed interval: a client that ignores the header spends its next window on requests that fail.

## Poll quota

Separately from the request limits, polls created through the API count against a monthly quota per space. Pro includes 50 polls a month. The space owner can raise the quota from the API keys settings page.

- The quota resets at the start of each calendar month in UTC.
- Only successful `POST /polls` requests count. A request that fails validation is not counted.
- Deleting a poll does not give its slot back.
- Polls created in Rallly itself never count.
- The space owner is emailed when the space reaches 80% of its quota, and again when it reaches 100%.

Every `POST /polls` response that passes authentication and the request limits carries three headers:

| Header | Meaning |
| --- | --- |
| `X-Poll-Quota-Limit` | Polls the space may create through the API this month |
| `X-Poll-Quota-Used` | Polls the space has created through the API this month. Can exceed the limit if the limit was lowered |
| `X-Poll-Quota-Reset` | When the count resets, as an ISO 8601 instant in UTC |

When the quota is used up, `POST /polls` responds with `429 Too Many Requests`, a `POLL_QUOTA_EXCEEDED` error body and a `Retry-After` header with the number of seconds until the reset.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 1036800
X-Poll-Quota-Limit: 50
X-Poll-Quota-Used: 50
X-Poll-Quota-Reset: 2027-01-01T00:00:00.000Z
```

```json
{
  "error": {
    "code": "POLL_QUOTA_EXCEEDED",
    "message": "This space has reached its monthly API poll quota. It resets at 2027-01-01T00:00:00.000Z. To raise it, add API capacity at https://app.rallly.co/settings/api-keys."
  }
}
```

Unlike a rate limit, `Retry-After` here can be days away. Do not retry: raise the quota, or wait for the reset. Reading, listing and deleting polls are unaffected.

## Store outages

If the rate limit store cannot be reached the API fails closed and responds with `503 Service Unavailable`, a `SERVICE_UNAVAILABLE` error body and a `Retry-After` header.
